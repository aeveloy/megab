# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Luau script hub for a Roblox executor. The UI is **our own library, `ui.lua`**; it replaced Rayfield Gen2. It copies the subset of the Gen2 API the modules use: lowercase props (`name`, `description`, `callback`, `flag`, `forgetState`), `Window:CreateTab/Notify/Unload/Get/Set`, `Window.Flags` (a proxy where writing calls `:Set` and fires the callback, iterable with `for k, v in Window.Flags`), and `Tab:CreateSection/Toggle/Slider/Dropdown/Button/Text`. If a module needs a new element or option, add it to `ui.lua` rather than calling Rayfield. Per-game values save to `<workspace>/megab/configs/<GameId>.json`. The global UI settings (theme and toggle key, chosen from the gear panel) save to `megab/settings.json`. Closing the window shows a round icon at the top center that reopens it. Theming works through `bind(inst, prop, themeKey)` plus `onTheme(fn)` refreshers, so new UI pieces must use those, or a theme switch won't recolor them. Icons are Lucide, stored as `{assetId, rectX, rectY}` (48px) in the `ICONS` table at the top of `ui.lua`, extracted from Rayfield's generated `icons.lua`. Add a new icon by looking up its entry there; `CreateTab` also takes `icon = "<lucide-name>"`. Themes with a `mascot = "<name>"` field (Claude, ChatGPT, Gemini) show `assets/<name>.png` as a faint watermark over the pages: `ui.lua` caches it in `megab/assets/`, downloads it once from `opts.assetBase` (the loader passes `REMOTE_BASE`), and displays it with `getcustomasset`; with no `getcustomasset` it just shows nothing. The mascots are original cute characters rendered with PowerShell System.Drawing, not the companies' logos. Tests can click UI buttons with `firesignal(button.MouseButton1Click)`. No build, lint, or test tooling exists. Scripts run inside the executor and get tested in a live Roblox client, for example through the `roblox-mcp` / `madium` / `potassium` MCP tools when they are connected. The loader reads `megab/ui.lua` from the workspace (or `REMOTE_BASE`), so `ui.lua` needs syncing there like the modules.

## Architecture

- On startup the loader shows `UI:CreateSplash` (a loading screen with the credit "made by @aeveloy and claudecode <3"). The window is created with `startHidden = true`, each load phase calls `splash:Step(text, progress)`, and after `splash:Finish()` it calls `Window:Open()`. Keep that credit text when editing.
- `loader.lua` is the single entry point. It loads `ui.lua`, creates the window (with config saving), loads one per-game module, and **then** creates the **Info** tab, so Info is always the last tab.
- In a game with no module, the loader builds one tab per entry in its `SUPPORTED` table (name, gameId, placeId, Lucide icon, about text), each with a `TeleportService:Teleport(placeId)` button. **When you add a game module, also add it to `SUPPORTED` in `loader.lua` and to the table in `README.md`.**
- The repo is public at https://github.com/aeveloy/megab, and `REMOTE_BASE` points at its raw `main` branch. Users run `loadstring(game:HttpGet("https://raw.githubusercontent.com/aeveloy/megab/main/loader.lua"))()`. Push to `main` to ship.
- Modules are keyed by **`game.GameId`** (universe ID, which is the same across every place in a game), not `PlaceId`. The file is `games/<GameId>.lua` (or `.luau` when loaded locally).
- Module lookup order:
  1. Local: `<executor workspace>/megab/games/<GameId>.lua` via `isfile`/`readfile`. The executor reads its own workspace, not this repo, so after editing a module, write the new content there too (e.g. `writefile` through an MCP execute call).
  2. Remote: `REMOTE_BASE .. "games/<GameId>.lua"`, only if `REMOTE_BASE` is set (it is `nil` by default).
- Module contract: `return function(Window, ctx) ... end`, where `ctx = { GameId, PlaceId, Name, onUnload(fn) }`. The module adds its tabs to `Window`. The loader wraps compile, run, and init in `pcall` and reports the result with `Window:Notify`.
- The loader stores `getgenv().megab = { Window, Unload }` and unloads any previous instance when it runs again, so re-running it never leaves duplicate windows or ESP. Use `getgenv().megab.Window.Flags` to drive toggles from MCP tests.
- Teardown: register cleanup with `ctx.onUnload(fn)`. The Info tab's **Unload hub** button runs those functions, then `Window:Unload()`. Rayfield's own UI can also unload the window, so long-running loops should also check `Window.unloaded` and clean up themselves.
- Config: `ui.lua` saves to `megab/configs/<GameId>.json`, applies saved values when each element is created, and fires the callback for saved toggles that were on. Give every value element an explicit `flag` (e.g. `mm2_esp_roles`) so saved files survive renames. `forgetState` elements are not saved and not reachable through `Window.Flags`.

## Games

- `66654135` Murder Mystery 2. Roles come from `ReplicatedStorage.Remotes.Extras.GetPlayerData:InvokeServer()` (`{[name] = {Role, Dead, ...}}`; Role is `Murderer`/`Sheriff`/`Hero`/`Innocent`). Holding a `Knife` or `Gun` tool takes priority, which covers the gun being picked up mid-round. Between rounds the table is empty. Tabs are "Basic" (ESP, everyone ESP, distance labels, dropped-gun ESP, role notify, murderer alert, teleports, auto grab gun) and "Farm" (coin ESP, coin farm, farm speed). The dropped gun is a part named `GunDrop` (verified in game). Coins are `Workspace.<Map>.CoinContainer.Coin_Server` parts, picked up by touch, and a coin counts as live while its child `CoinVisual` has Transparency < 1. Player Highlights share Roblox's limit of about 31 per client, so whole groups (e.g. all coins) get one Highlight on their container.

- `383310974` Adopt Me!. Game modules load with `require(ReplicatedStorage.Fsys).load(name)`. Remotes come from `RouterClient.get("API/Name")` and are plainly named in `ReplicatedStorage.API`. Player state is `ClientData.get_data()[LocalPlayer.Name]`. Teleports use `InteriorsM.enter(dest, door, settings)`: from an interior back to the map the door is `"<Interior>/MainDoor"`, and for home use `"housing"` with `{ house_owner = LocalPlayer }`. Pet needs are `ailments_manager.ailments[pet_unique][kind]`, defined in `ReplicatedStorage.new.modules.Ailments.AilmentsDB.<kind>`. Location needs complete after about 50s in the right interior or map area. **Pets do not follow `InteriorsM.enter`**, so after a teleport, re-equip them next to you (`ToolAPI/Unequip` then `ToolAPI/Equip(uid, { spawn_cframe })`). Owned pet models come from `PetEntityManager.get_local_owned_pet_entities()[i].base.char`, and `unique_id` is `"<pet_unique>-<userId>"`. Furniture needs use `HousingAPI/ActivateFurniture(LP, furnitureUnique, useBlockName, { cframe }, petChar)`, where each furniture folder in `Workspace.HouseInteriors.furniture` is named `.../<unique>` and holds the kind Model plus `UseBlocks`. The bathtub (dirty) and bed (sleepy, about 50s) are verified in game. Play is verified (about 3 throws, 18s): `ToolAPI/Equip(toyUid)`, then `load("ThrowToyHelper").generic_throw_toy_use(inventoryItem, targetPos, { reaction_name = "ThrowToyReaction" })`. Re-equip before each throw, because throwing unequips the toy. `pet_me` is **unsolved**: `AdoptAPI/FocusPet`, then `PetAPI/PetPetted(uid, LP)`, then `AilmentsAPI/ProgressPetMeAilment(uid)` (the game's order) does not clear it, and `FocusPetApp.petting_handler:start_petting()` blocks waiting for mouse input. The `Auto Pet Needs` toggle is `forgetState`, so tests drive it with `Window.megabHandles.autoPet:Set(true)`, and every hub reload turns it off. Walk and ride use RateMovement, which counts about 30s of time spent *moving*, so the hub keeps the character walking in a circle. Walk: `AdoptAPI/HoldBaby:InvokeServer(petChar)`, then `AdoptAPI/EjectBaby:FireServer(petChar)` to drop. Ride needs a stroller, because ride also checks the player's state and holding doesn't count: `ToolAPI/Equip(strollerUid)`, then `AdoptAPI/UseStroller:InvokeServer(LP, petChar, StrollerTool...TouchToSit)` (verified, about 35s). Still unsupported: pet_me, at_work, mystery, party_zone.

- `73885730` Prison Life. Guns come from `Remotes.InteractWithItem:InvokeServer(anyPartOf(Workspace.Prison_ITEMS.giver.<Gun>))`. You must be within about 12 studs, so teleport next to the gun and back. The call returns a message string, and the limit is 2 primary guns. M4A1 is excluded because invoking it opens a gamepass purchase prompt, which also disconnected the MCP client once. Teams change with `Remotes.RequestTeamChange:InvokeServer(Team, 1)`: going Guards to Inmates directly is refused, so go through `Teams.Neutral` first. An Inmate who teleports to the criminal base spawn `(-975, 105, 2057)` becomes a Criminal instantly. Wrap InvokeServer calls in a timeout, because some of them never return.

## Conventions

- Guard executor-only globals (`isfile`, `readfile`, `setclipboard`, `gethui`, …) with `typeof(x) == "function"` or `pcall`, because support differs between executors.
- Visuals such as Highlights go in a folder under `gethui()` (falling back to CoreGui), not under game instances.
